## Commands

```bash
npm run dev                              # http://localhost:3000 (/ redirects to /kalender)
npm run build                            # also validates Cache Components rules
npm run lint && npm run typecheck
npm test                                 # vitest, all tests
npx vitest run src/lib/crypto.test.ts    # one file
npx vitest run -t 'rejects a tampered'   # one test by name
npm run worker                           # publishing worker; separate process, reads .env.local if present
npm run db:push -- --db-url "<postgres-url>"   # apply supabase/migrations (Supabase is self-hosted on the VPS)
ngrok http --url=<domain> 3000           # public URL (e.g. x.ngrok-free.dev); in dev, open the app there, not on localhost
```

After `npm install <pkg>`, check `git diff package-lock.json`: npm 11 has dropped the `@rolldown/binding-*` optional dependencies from the lockfile here, after which vitest fails with "Cannot find native binding". Restore the lockfile and add only the new package's entries. Stop `npm run dev` before `npm ci`: on Windows the dev server holds lightningcss's `.node` file, and `npm ci` deletes most of `node_modules` before failing with EPERM.

## Next.js 16.4 specifics

- This Next version differs from training data. Read the bundled guides in `node_modules/next/dist/docs/` before writing Next code (see `AGENTS.md`).
- `cacheComponents` and `partialPrefetching` are on. Request-time reads (Supabase, `searchParams`, `headers()`, current time) must sit inside `<Suspense>`. Call `await connection()` before reads that can resolve without an uncached fetch, or the result gets prerendered at build time (this happened to the sidebar status when Supabase env was empty). In the `npm run build` route table, pages with live data should show ◐, not ○.
- `src/proxy.ts` replaces `middleware.ts`.

## Architecture

- **Users and sessions.** Supabase Auth with email and password (`/masuk`, `/daftar`, actions in `src/app/masuk/actions.ts`). Self-hosted Supabase has no SMTP, so it runs with `ENABLE_EMAIL_AUTOCONFIRM=true`: no confirmation mail, no password reset. `src/lib/auth.ts` builds the cookie-based client from `@supabase/ssr` (auth only, never data) and exposes `currentUser()` and `requireUser()`, which read the session with `getClaims()`; `getSession()` would trust the cookie unverified. `src/proxy.ts` refreshes the session on every request and sends visitors without one to `/masuk?next=…`; only `PUBLIC_PATHS` there (`/masuk`, `/daftar`, `/privasi` for the Meta app) and `WEBHOOKS` (Meta's and Mayar's) skip it. New public endpoints go in that set. Every page loader, route handler and server action still calls `requireUser()` itself, outside any `try`, because its `redirect()` throws. Session cookies belong to one host, and the OAuth callbacks read the session, so `APP_URL` and the dashboard must be on the same domain as the callbacks: in dev, open the ngrok domain, not localhost. The Meta app's OAuth redirect URI is that domain with a trailing slash (`INSTAGRAM_REDIRECT_URI=https://<domain>/`; the token exchange fails without the slash), so `src/proxy.ts` rewrites `/?code=…` and `/?error=…` to the callback route and `next.config.ts` skips its `/` redirect for them.
- **Server-only code.** Modules in `src/lib` that touch secrets `import 'server-only'`. Vitest aliases that import to a stub (`vitest.config.mts`).
- **Data access and tenancy.** `db()` in `src/lib/supabase.ts` is the service-role client. Tables have RLS on with no policies, so the publishable key can read nothing; that stays, because RLS policies would let users write their own rows directly and skip the post lock and the AI limit. Isolation lives in `src/lib`: every data function takes `userId` first and filters with `.eq('user_id', userId)` (or passes `p_user_id` to an SQL function), and every table carries `user_id` referencing `auth.users` with `on delete cascade`. Former singletons (`instagram_connections`, `facebook_connections`, `brand_kit`, `dm_settings`) are keyed by `user_id`. DM keys are `(user_id, igsid)` and `(user_id, mid)`, because two users of the app messaging each other see the same `mid`. `save_post` refuses another user's photos. A `before delete` trigger on `auth.users` removes the user's posts first, since `post_media` restricts deleting a photo in use. Rows from before multi-user belong to the first auth user (`20261016040000_multi_user.sql`). New Storage objects go under `<userId>/`. Schema changes go in new files under `supabase/migrations/`.
- **Instagram connection.** Lives in `src/lib/connection.ts`: one `instagram_connections` row per user, with `instagram_user_id` unique, so an account connected by another user fails with `AccountTakenError` (`?ig_error=akun_dipakai`). One-time `oauth_states` record the user who started the login, and the callbacks redeem a state only for that same signed-in user, so a login link someone else started can't attach their account to yours. Raw HTTP to Instagram is in `src/lib/instagram.ts`. Anything that calls Instagram gets its token from `getValidAccessToken()`, which decrypts it, refreshes it lazily (when older than 24 hours and within 7 days of expiry), and flips status to `needs_reconnect` on Graph error 190.
- **Tokens.** Encrypted with AES-256-GCM using `TOKEN_ENCRYPTION_KEY`. Changing the key makes stored tokens unreadable, so the owner must reconnect.
- **Logging.** Graph API GETs carry `access_token` in the query string. Never log URLs or raw fetch errors; log through `describeError()`.
- **OAuth errors.** They reach the browser only as `?ig_error=<code>`, mapped to Indonesian messages in `src/app/(app)/pengaturan/instagram-settings.tsx`.
- **Posts.** Tables `assets`, `posts`, `post_media`, `publish_attempts`; data access in `src/lib/posts.ts` and `src/lib/assets.ts`. Post content changes only through the `save_post()` SQL function, which swaps caption, schedule and photos in one transaction and raises `post_locked` for posts the worker owns. Status-only changes (cancel, retry, delete) are conditional updates that report whether they won.
- **No duplicate posts.** A non-null `posts.ig_container_id` means Instagram may already have published the post, so its content stays locked. The worker saves the container id before `media_publish`, checks the container's `status_code` before any retry (`PUBLISHED` means done), and clears the id only when it is certain the post did not go out.
- **Worker.** `src/worker/` runs apart from Next via `tsx` with `--conditions=react-server`, which makes `server-only` resolve to an empty module. It polls `claim_due_post()` (`FOR UPDATE SKIP LOCKED`; a post stuck in `publishing` for 10 minutes is reclaimed) and retries transient errors after 1/5/15/30 minutes, at most 5 attempts. In production it runs on the VPS next to Supabase under pm2 or systemd.
- **Media.** Photos are cropped to 4:5–1.91:1, capped at 1440 px and re-encoded as JPEG in the browser (`toInstagramJpeg`) before upload. The `media` bucket is private; Meta gets signed URLs built from `NEXT_PUBLIC_SUPABASE_URL`, so that must be the public HTTPS domain, not an internal address. Signed URLs carry a token: never log them.
- **DMs.** Meta posts DMs to `src/app/api/webhooks/instagram/route.ts`. The GET handler answers the verify handshake (`INSTAGRAM_WEBHOOK_VERIFY_TOKEN`). The POST handler hashes the raw body and checks `X-Hub-Signature-256` against `INSTAGRAM_APP_SECRET` before parsing it (`src/lib/dm-webhook.ts`). It hands each `entry.id` to the user who connected that account (`findUserByInstagramId`) and drops the rest, and it answers 5xx only when storing fails, because Meta retries those. Every message goes through `record_dm_message()`, keyed on Meta's `mid`. That makes retries and the echo of the app's own sends no-ops, and a late webhook never moves a conversation's summary or its 24-hour window. Replies go out from a server action (`sendDirectMessage`, Bearer token, JSON body), and only within 24 hours of the customer's last message. Meta delivers webhooks only once the app is Live, and each account must be subscribed once with the **Aktifkan DM** button (`/me/subscribed_apps`). Template matching and filling are pure functions in `src/lib/dm-templates.ts`: a keyword must appear as a whole word, case-sensitive, as the owner chose. Templates only ever fill the editable draft.
- **Time.** Schedules are entered and shown in WIB (fixed +07:00, `src/lib/format.ts`); the database stores UTC.
- **AI.** `src/lib/nine-router.ts` is the raw HTTP client. `src/lib/ai.ts` validates requests, builds the prompts, reads the answers, logs every request to `ai_generations` and charges every request `TASK_CREDITS` (`src/lib/billing-options.ts`) against the period's `PLAN.credits`, counted with `credits_used()` from that table; failed requests cost 0. Choices shared with the editor live in `src/lib/ai-options.ts`. Requests must send `stream: false`, or 9Router answers with SSE. A 200 can carry a provider notice instead of an answer, so only JSON that passes `parseOptions` counts as success. The `/buat` panel (`ai-assistant.tsx`) renders inside the post form, but its fields belong to a separate empty form (`AI_FORM_ID`, via the `form` attribute): otherwise Enter in a panel input submits the post with Jadwalkan, and React's form reset after a save shows the dropdowns' first options while state keeps the owner's choice. A failed `ai_generations` count blocks AI requests rather than reading as 0 (postgrest-js returns no error and no count for a HEAD 404). `runLogged()` wraps every 9Router call, brand tasks included, with that limit and log. `runAiTask` adds the saved brand kit's text (`getBrandContext()`) to every prompt, and brand facts count as facts the model may use. A brand kit that fails to load leaves captions unbranded instead of failing them.
- **Langganan.** Payments are off unless `MAYAR_ENABLED=true` (`paymentsEnabled()`): while testing, sign-up grants a free period (`grantFreePeriod`, an amount-0 row through the same `activate_payment`) and the button on `/langganan` grants another, so credits and expiry still behave as with paid periods. A subscription is not a table: a user is active while a `paid` row in `payments` covers now (`getCurrentPeriod`, `src/lib/billing.ts`), and `activate_payment()` starts the next period at the end of the last one, so paying early stacks. `requireActiveUser()` (`src/lib/auth.ts`) gates every `(app)` page, its actions and the OAuth routes; `/langganan` itself only needs a session. Checkout is a Mayar Single Payment Request (`src/lib/mayar.ts`): the `payments` row is written before Mayar is asked, and an open link is handed out again instead of creating another. Mayar signs no webhooks, so `/api/webhooks/mayar` only names payments, and a payment counts as paid only when Mayar's API answers `paid` for the same amount to our key (`confirmPayment`). Opening `/langganan` checks pending payments too, so a lost webhook only delays activation. The worker fails posts of users whose period ended, keeping any container. The owner's free period (to 2099) is a `payments` row with amount 0; other free accounts get the same row by hand. The webhook's id field (`webhookPaymentIds`) is a guess (`productId`, then `id`) until checked against Mayar's webhook history in sandbox.
- **Brand kit.** Tables `brand_kit` (one per user), `brand_references` and `facebook_connections` (one per user); data access in `src/lib/brand.ts`, shared fields and validation in `src/lib/brand-options.ts`, prompts in `src/lib/brand-ai.ts`. Images live in the private `brand` bucket (JPEG, PNG, WebP), apart from `media`, so other accounts' photos never reach the post picker. Profile and visual-style analysis only fill the form; the owner saves. Palettes are computed in the browser from pixels (`src/lib/palette.ts`); the fetch uses `cache: 'no-store'` because Storage sends no `Vary: Origin` and the card's `<img>` would otherwise leave a cached copy without CORS headers. Anything fetched from outside goes through `fetchPublic()` (`src/lib/web-fetch.ts`), which refuses loopback and private hosts at every redirect and caps the size. Website reading is regex over HTML and CSS, without a parser dependency (`src/lib/website.ts`).
- **Business Discovery.** Reading other accounts needs Facebook Login (`src/lib/facebook.ts`, routes under `src/app/api/auth/facebook/`, the callback in `PUBLIC_PATHS`), separate from Instagram Login. The callback keeps a Page token derived from a long-lived user token, which does not expire. It picks the Page whose Instagram account is the connected one. `FACEBOOK_LOGIN_CONFIG_ID` switches the dialog from `scope` to Facebook Login for Business. The username is interpolated into Graph field syntax, so `parseInstagramUsername()` must keep it to `[a-z0-9._]`.
- **Gambar AI.** `src/components/image-generator.tsx` is shared by `/studio` (Simpan ke Aset) and the post editor's Gambar AI panel (Pakai di post, fields on `AI_FORM_ID`). Server actions live in `src/app/(app)/studio/actions.ts`, logic in `src/lib/image-ai.ts`, shared choices in `src/lib/image-options.ts`. A Haiku plan decides how many slides the content needs (1–10). All text that appears in an image belongs in the slide's headline: the prompt quotes it exactly, and without one it forbids any text, because the model otherwise adds words of its own. `generateImage()` asks 9Router for SSE (`progress` events keep the connection open through nginx; `done` carries `b64_json`, `error` a message) and JPEG. Input images (slide 1 for consistency, a brand reference, the logo) go as data URLs in `images[]` and are packed into `VISUAL_BODY_BUDGET`; 9Router forwards URLs to OpenAI, which needs HTTPS. Results stay in the browser until the owner saves them through `prepareAndUpload()`, the same crop and upload as a manual photo. Logs keep the prompt and the byte count, never image data.

## Rules carried from the PRD

- AI output and Auto DM templates are always an editable draft. Nothing publishes or sends a DM without an explicit owner action. No bulk or unsolicited DMs, and no scraping.
- Scheduled publishing runs in the worker process (`npm run worker`), never in the browser or the Next server.
- Meta cannot fetch `localhost` media. Publish from Supabase Storage URLs.
- 9Router is called only from server code. Images come from `ROUTER_IMAGE_MODEL` (default `cx/gpt-image-2.5`, working after the owner updated 9Router on 2026-10-16; before that the Codex provider refused every image model). `/v1/models` does not list image models; the 9Router dashboard does. The PRD names the `Hermes-daily` combo, but on 2026-10-16 it answered every request with "Gemini 3.5 Flash is no longer available…", so `ROUTER_MODEL` is `cc/claude-haiku-4-5-20251001`. Verify a new `ROUTER_MODEL` with a live request; the tests mock 9Router. Vision works with `image_url` data URLs (2026-10-16). Request bodies pass an nginx with the default 1 MB `client_max_body_size` (HTTP 413 above it), so visual analysis packs references into `VISUAL_BODY_BUDGET`. Image URLs need HTTPS, which the Storage URL isn't yet. After a provider error 9Router may answer the next requests with the same error and "reset after 30s".
- `INSTAGRAM_ACCESS_TOKEN` in `.env.local` is a manual test token. The app does not use it.
